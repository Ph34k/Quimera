## 2024-05-27 - Hardcoded PostgreSQL Credentials in Configuration
**Vulnerability:** The application stored default development database credentials directly in `app/core/config.py` as fallback values for `os.getenv`. This meant that if the environment variables weren't set, the app could potentially try to connect to a default database, which is a known pattern for credential leakage and unauthorized access if those defaults are ever publicly exposed or accidentally used in environments that should be secure.
**Learning:** Even default "dev" credentials should not be hardcoded in the primary application codebase. It's much safer to require explicit configuration via environment variables or a secure configuration management system. Hardcoded secrets are a persistent security risk. Also, avoid removing non-sensitive defaults (like Redis) if they don't contain passwords, as it can cause unnecessary application crashes without providing any security benefit.
**Prevention:** Remove fallback values for sensitive environment variables in `app/core/config.py`. Enforce explicit configuration by setting the type hint to `Optional[str]` and raising a clear runtime exception during initialization (e.g., in `app/infrastructure/database.py`) if the required configuration is missing, creating a "fail-safe" default posture.
