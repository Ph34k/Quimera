## 2024-05-15 - [SSRF in HTTPx Client Execution]
**Vulnerability:** The application's `IScoutAgent` and `IExecutionAgent` were executing user-provided URLs via `httpx.get` without any validation, allowing for Server-Side Request Forgery (SSRF). Attackers could use these agents to scan internal networks, access loopback addresses, or interact with private AWS metadata endpoints.
**Learning:** Preventing SSRF requires deep validation (IP resolution via `socket.getaddrinfo`) as a primary defense. Note: A complete defense against DNS rebinding (TOCTOU) requires a custom HTTP transport or resolver, which is out of scope for a basic hook.. Additionally, since `IExecutionAgent` explicitly follows redirects (`follow_redirects=True`), URL validation must occur at the request level via an `httpx` event hook (`verify_request`) to catch malicious redirects that try to bounce from public to private IPs.
**Prevention:** Implement `is_safe_url` checking against `ipaddress` rules (private, loopback, link_local) for all resolved IPs, and inject this validation into the `httpx.Client` using the `event_hooks={'request': [verify_request]}` parameter to ensure both the initial request and all subsequent redirects are validated.
