## 2024-05-16 - Prevent SSRF in Agent HTTP Requests
**Vulnerability:** The application was using direct `httpx.get()` calls to process user-provided URLs in `IScoutAgent` and `IExecutionAgent` without checking if the target domains resolved to internal or private IP ranges. This could allow an attacker to bypass firewalls and scan or interact with internal network services (SSRF).
**Learning:** Even when performing legitimate web requests as part of a service (like an OSINT or execution agent), all user-provided URLs must be intercepted and validated before execution, not just at the API boundary, since basic string checks can be circumvented (though full DNS rebinding defense requires transport-level IP pinning).
**Prevention:** Implement a `verify_request` event hook in the persistent `httpx.Client` to resolve the hostname via `socket.getaddrinfo` and block private, loopback, link-local, and unspecified IP ranges. Note: while this intercepts basic SSRF, a true defense against DNS rebinding (TOCTOU) would require a custom HTTP transport to pin the resolved IP.
