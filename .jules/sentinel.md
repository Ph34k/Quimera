## 2024-05-27 - SSRF Vulnerability in Quimera Agents
**Vulnerability:** IScoutAgent and IExecutionAgent were performing real HTTP requests directly using user-supplied URLs without any validation or sanitization, introducing a critical Server-Side Request Forgery (SSRF) risk. This allowed querying internal networks, localhosts, and cloud metadata APIs (like 169.254.169.254).
**Learning:** External user input was passed directly to the `httpx.get` method under the assumption that agents would naturally resolve safe, valid external targets. Because the client was not configured to filter out private IP spaces or internal loopback addresses, it acted as a proxy into the isolated environment.
**Prevention:** Implement `is_safe_url` utilizing `socket.getaddrinfo` and `ipaddress` validation prior to request execution. Enforce it using a persistent `httpx.Client` injected with an event hook (`verify_request`) to secure any further HTTP redirects that may point to forbidden internal spaces. Keep in mind that TOCTOU DNS rebinding is not fully prevented by this alone unless a custom HTTP transport resolves and pins the safe IP, but this mitigates standard SSRF significantly.
