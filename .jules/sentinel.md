## 2025-02-18 - Remove Hardcoded Production Credentials
**Vulnerability:** A hardcoded default fallback (`default_secret_key_for_dev`) was being used for `SECRET_KEY` in `app/core/config.py`. If the environment variable was omitted in production, the system would silently default to an insecure, known key, allowing trivial exploitation of signed payloads like JWTs.
**Learning:** Using `os.getenv("SECRET_KEY", "default")` inside dataclasses creates a risk where the development fallback leaks into production if not explicitly guarded. Relying on `__post_init__` for this guard is dangerous, as plain Python classes masquerading as config singletons (e.g., without the `@dataclass` decorator actually applied or without `__init__` being properly triggered) may skip executing `__post_init__` entirely, silently bypassing the security check.
**Prevention:** Enforce environment variable presence securely at module load time or within explicit helper functions (e.g., `_get_secret_key()`) that execute unconditionally. Raise `ValueError` immediately if required production variables are missing, establishing a fail-safe configuration boundary.
